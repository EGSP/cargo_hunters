# Инвентарь по дереву UI: 15 октября 2026 года

Инвентарь открыт событием клавиши Tab через Unity Input System в сохранённом хабе `Shelter_02_TruckStop`. Проверены закрытие, повторное открытие и автоматическое отпускание клавиши. Запросы отправлялись напрямую по HTTP из терминала через curl и Python urllib.

## Область исследования

В первоначальном исследовании UI использовались дерево сцены, имена и типы компонентов, экранные прямоугольники RectTransform, текст и флаг enabled компонентов TextMeshPro. Тогда поля моделей и ItemViewDataAdapter не читались, сейв не разбирался и сканирования памяти не было. Позднее для сетевой JSON-выгрузки добавлено чтение игровых интерфейсов предметов и контейнеров; описание команды приведено в [dev-bridge.md](dev-bridge.md).

## Наблюдаемая структура

Сокращённое дерево с опущенными промежуточными панелями:

```text
CharacterLootingItemsContainer_View_Shelter
├─ LeftHalf
│  └─ Equipment_Container / Equipment_View
│     └─ PrimaryWeapon_EquipSlot
│        └─ EquipSlot_View(Clone)_0                 [EquipSlotView]
│           └─ Slot / ItemRect
│              └─ Item_View_InEquipSlot             [ItemView, ItemViewDataAdapter]
└─ RightHalf
   └─ Inventory_Rect / Inventory_Placement
      └─ PageItemContainer_Widget(Clone)             [PageItemsContainerController]
         └─ ... / ItemsContainer_View               [SplittedItemsContainerView, ItemsContainerController]
            └─ ItemsContainer
               └─ ItemsContainer_ViewWithoutController(Clone) [ItemsContainerView]
                  ├─ VisualGrid                     [VisualGridView]
                  └─ ItemsContainer
                     └─ Item_View(Clone)            [ItemView, ItemViewDataAdapter]
                        ├─ QuantityLabel
                        └─ Title / ShortNameLabel
```

Класс контейнера отличается от класса предмета явно, по компонентам:

| Роль UI | Компоненты |
| --- | --- |
| Представление предмета | `Game.UI.Views.ItemView`, `Game.UI.Views.ItemViewDataAdapter` |
| Представление контейнера | `Game.UI.Views.ItemsContainerView`, `Game.UI.Views.SplittedItemsContainerView` |
| Контроллер контейнера | `Game.UI.Controllers.ItemsContainerController` |
| Страницы хранилища | `Game.UI.Views.PageItemsContainerController` |
| Сетка | `Game.UI.Views.VisualGridView` |
| Слот экипировки | `Game.UI.Views.EquipSlotView` |

Обнаружены отдельные слоты основного и дополнительного оружия, пистолета, ближнего боя, разгрузки, брони, шлема и инструментов. Это наблюдение о UI, не полная спецификация системы экипировки.

## Что видно у предметов

- У экземпляра UI есть Unity InstanceID, родитель в дереве, экранный прямоугольник, дочерняя иконка Image и надписи.
- В проверенном поддереве текущей страницы хранилища найдено 83 объекта с `ItemView`. При глубине 8 вернулось 2301 узел, лимит 3000 не достигнут. Это счётчик представлений текущей страницы, не полный инвентарь всех страниц и вложенных контейнеров; более глубокие декоративные ветви могут быть обрезаны глубиной.
- Примеры подписей при включённом TMP-компоненте: «ETA 5» — `50/50`, «ETA 45» — `25/25`, «SAPA12» — `8/8`, «Гидравлическая жидкость» — `1`. Разметка и служебные последовательности в исходных строках сохранены в JSON; здесь подписи упрощены для чтения. Смысл чисел не выводился из модели предмета.
- Есть названия «Ящик для предметов», «Тиски», «Сковорода», «Ударная дрель». У части предметов QuantityLabel выключен — его оставшийся текст не является текущим количеством.
- У экипированного предмета «1А4М» включены подписи `30/30` и `5.56x45`. В его выключенных TMP-компонентах лежат `$999999` и `midle text`; они исключены из фактов о предмете.

## Практические ограничения

`Item_View(Clone)` повторяется у множества соседних объектов, поэтому даже полный путь по именам может совпадать. Для текущего снимка использовать InstanceID и связь родитель–ребёнок; это не постоянный ID игрового предмета.

Родительский `ItemsContainerView` позволяет определить размещение UI-предмета в показанной сетке. Это не доказывает все связи владения в игровой модели. Сумка или ящик могут иметь собственную иконку ItemView, а открытая сетка их содержимого — отдельное представление контейнера. Для закрытых контейнеров, других страниц и виртуализированных элементов UI может ещё не быть создан.

Дерево уже позволяет построить карту `itemViewId → containerViewId → подписи → экранный прямоугольник`. Для последующего взаимодействия имеет смысл опираться на типы компонентов и проверять состояние UI, а не искать предметы только по именам GameObject. Точные template ID, постоянный item ID, параметры модели и контракт перестановок этим исследованием не установлены.

## Кнопка сортировки

В меню «Фильтры» найден пункт «Сортировать»: `DropdownList_View_AutoSize_Highlight/ContentRect/DropdownList_View_AutoSize_Highlight_Button_0/Button_Base_Small`, дочерняя надпись `Label` содержит «Сортировать». Кнопка нажата через `/ui/click` с успешной проверкой raycast. После нажатия меню закрылось, модальное подтверждение не появилось.

Сравнение текущей страницы до и после: 83 ItemView в обоих снимках, набор подписей совпал, экранные прямоугольники не изменились. Доставка клика подтверждена, изменение раскладки не зафиксировано. По этому результату нельзя установить, уже ли была отсортирована страница или действие не изменяет раскладку по другой причине.

Снимки и сравнение: `docs/diagnostics/sort-before.json`, `sort-after.json`, `sort-result.json`.
